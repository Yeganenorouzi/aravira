# 🌸 سامانه نوبت‌دهی آنلاین سالن زیبایی

وب‌اپلیکیشن کامل رزرو نوبت آرایشگاه و سالن زیبایی، با رابط کاربری **فارسی و راست‌چین**، **تقویم شمسی**، و **اطلاع‌رسانی پیامکی و ایمیلی**.

رابط کاربری بر اساس طرح موبایل ارسال‌شده (تم رُز/صورتی) پیاده‌سازی شده است.

---

## شروع سریع

```bash
npm install          # نصب وابستگی‌ها
npm run seed         # ساخت داده‌ی نمونه (خدمات، پرسنل، مشتری آزمایشی)
npm run dev          # اجرای همزمان سرور و رابط کاربری
```

سپس در مرورگر باز کنید:

| آدرس | توضیح |
|---|---|
| <http://localhost:5173> | برنامه‌ی مشتریان (حالت توسعه) |
| <http://localhost:5173/admin/login> | پنل مدیریت |
| <http://localhost:4000/api/health> | بررسی سلامت سرور |

**حساب مدیر پیش‌فرض:** نام کاربری `admin` — رمز `admin123`
(در `.env` با `ADMIN_PASSWORD` قابل تغییر است؛ پس از اولین اجرا از خود پنل عوض کنید.)

### اجرای نسخه‌ی نهایی

```bash
npm run build        # ساخت نسخه‌ی production رابط کاربری
npm start            # سرور، هم API و هم رابط کاربری را روی پورت ۴۰۰۰ سرو می‌کند
```

## ورود مشتری بدون پنل پیامکی

در حالت پیش‌فرض سرویس پیامک روی **حالت آزمایشی** است: پیامک‌ها واقعاً ارسال نمی‌شوند و در
ترمینال سرور چاپ می‌گردند. کد ورود در همان صفحه‌ی ورود هم نمایش داده می‌شود تا بتوانید بدون
پنل پیامکی برنامه را تست کنید.

## امکانات

### برنامه‌ی مشتریان
- ورود با **شماره موبایل و کد یک‌بارمصرف پیامکی** (بدون نیاز به رمز عبور)
- صفحه‌ی اصلی با خدمات پرطرفدار، پیشنهادهای ویژه و نوبت پیش رو
- فهرست و جستجوی خدمات با دسته‌بندی
- صفحه‌ی جزئیات خدمت (مدت، قیمت، تخفیف، آرایشگران)
- انتخاب آرایشگر بر اساس تخصص و امتیاز
- **تقویم شمسی** با نمایش ظرفیت هر روز و فهرست ساعت‌های آزاد
- میانبر «زودترین زمان‌های آزاد»
- صورتحساب کامل (تخفیف، مالیات، بیعانه) و انتخاب روش پرداخت
- مدیریت نوبت‌ها: مشاهده، **جابه‌جایی** و **لغو**
- پروفایل، باشگاه مشتریان و امتیاز، تاریخ تولد شمسی

### باشگاه مشتریان و بازاریابی
- **کد تخفیف** درصدی یا مبلغ ثابت، با سقف تخفیف، حداقل خرید، محدودیت تعداد کل و
  به ازای هر مشتری، محدود به خدمات خاص، بازه‌ی اعتبار شمسی و حالت «فقط اولین نوبت»
- **کارت هدیه** با کد خودکار، موجودی قابل خرج در چند نوبت و ارسال پیامکی به گیرنده
- **سطح‌بندی باشگاه** (برنزی / نقره‌ای / طلایی) بر اساس مجموع خرید، با تخفیف دائمی
  و ضریب امتیاز برای هر سطح — تخفیف سطح خودکار روی فاکتور اعمال می‌شود
- **امتیاز و اعتبار**: با هر خرید امتیاز جمع می‌شود و در نوبت‌های بعدی خرج می‌گردد؛
  هر تغییر در دفتر گردش حساب ثبت و برای مشتری و مدیر قابل مشاهده است
- **دعوت از دوستان**: هر مشتری کد معرف اختصاصی دارد؛ پاداش هر دو طرف پس از اولین
  نوبت انجام‌شده پرداخت می‌شود (ضد سوءاستفاده)
- **نظرسنجی**: پس از هر نوبت از مشتری درخواست نظر می‌شود، امتیاز آرایشگر و خدمت
  خودکار بازمحاسبه می‌گردد و مدیر می‌تواند نظرها را منتشر، پنهان یا به آن‌ها پاسخ دهد

ترتیب محاسبه‌ی فاکتور:
`مبلغ خدمت − تخفیف خدمت − تخفیف سطح − کد تخفیف + مالیات − امتیاز − کارت هدیه − اعتبار`

هنگام لغو نوبت، کد تخفیف، موجودی کارت هدیه، امتیاز و اعتبار به‌صورت خودکار برمی‌گردند.

### پنل مدیریت
- داشبورد: نوبت امروز، درآمد، نمودار هفتگی، پرطرفدارترین خدمات
- مدیریت نوبت‌ها با فیلتر وضعیت/تاریخ/جستجو و تغییر وضعیت
- مدیریت خدمات (قیمت، مدت، تخفیف، دسته، آیکون)
- مدیریت پرسنل (شیفت کاری، روزهای تعطیل، خدمات قابل ارائه)
- مشتریان (CRM): سطح باشگاه، امتیاز، اعتبار، شارژ دستی، گردش حساب، یادداشت و مسدودسازی
- **تخفیف و باشگاه**: کد تخفیف، کارت هدیه و مدیریت نظرها
- **مرکز پیام‌رسانی**: ارسال پیامک/ایمیل تکی و گروهی با قالب و متغیر
- تنظیمات: اطلاعات سالن، ساعات کاری، تعطیلات، قواعد رزرو، سرویس پیامک و SMTP،
  سطح‌های باشگاه، پاداش دعوت و نظرسنجی

### اطلاع‌رسانی خودکار
| رویداد | پیامک | ایمیل |
|---|:---:|:---:|
| کد ورود | ✓ | — |
| ثبت نوبت | ✓ | ✓ |
| تأیید نهایی توسط مدیر | ✓ | ✓ |
| یادآوری پیش از نوبت (پیش‌فرض ۲۴ ساعت) | ✓ | ✓ |
| لغو نوبت | ✓ | ✓ |
| خوش‌آمدگویی عضو تازه | ✓ | ✓ |
| تبریک تولد + کد تخفیف | ✓ | ✓ |
| درخواست نظر پس از نوبت | ✓ | ✓ |
| صدور کارت هدیه | ✓ | ✓ |
| پاداش دعوت از دوستان | ✓ | ✓ |

زمان‌بند داخلی هر ۱۵ دقیقه نوبت‌های نزدیک، تولدهای امروز و نوبت‌های در انتظار نظر را بررسی می‌کند.
در پنل مدیریت دکمه‌ی «اجرای دستی یادآوری‌ها» هم وجود دارد.

## ماژول‌ها و لایسنس

برنامه ماژولار است و هر ماژول جداگانه فروخته می‌شود. فعال بودن ماژول‌ها با یک
**لایسنس امضاشده (Ed25519)** تعیین می‌گردد: شما با کلید خصوصی لایسنس صادر می‌کنید و
برنامه فقط با کلید عمومی آن را تأیید می‌کند. بنابراین مدیر سالن نمی‌تواند خودش ماژول
پولی را روشن کند و لایسنس هم قابل جعل نیست.

| ماژول | شناسه | وضعیت |
|---|---|---|
| هسته‌ی نوبت‌دهی | `core` | همیشه فعال |
| اطلاع‌رسانی پیشرفته | `notifications` | آماده |
| باشگاه مشتریان و بازاریابی | `marketing` | آماده |
| حسابداری و صندوق | `accounting` | به‌زودی |
| انبار و فروش محصولات | `inventory` | به‌زودی |
| ربات تلگرام مدیریت | `telegram` | به‌زودی |

قیمت‌ها و فهرست امکانات هر ماژول در [`server/lib/modules.js`](server/lib/modules.js)
تعریف شده‌اند و در پنل مدیریت ← **ماژول‌ها** نمایش داده می‌شوند.

### یک‌بار در ابتدای کار: ساخت کلید

```bash
npm run license:keygen
```

دو فایل ساخته می‌شود:

- `license-private.pem` — **نزد شما بماند.** در `.gitignore` قرار دارد و هرگز نباید
  همراه برنامه به مشتری داده شود. حتماً نسخه‌ی پشتیبان بگیرید؛ اگر گم شود دیگر
  نمی‌توانید لایسنس تازه صادر کنید.
- `server/license-public.pem` — همراه برنامه به مشتری داده می‌شود.

### صدور لایسنس برای هر مشتری

```bash
npm run license:issue -- --salon "سالن زیبایی رز" --modules marketing,notifications
npm run license:issue -- --salon "سالن نگین" --all --months 6
npm run license:issue -- --salon "سالن آوا" --modules marketing --expires 1406/09/30
```

گزینه‌ها: `--all` (همه‌ی ماژول‌ها) · `--months` (پیش‌فرض ۱۲) · `--expires` (تاریخ شمسی)
· `--perpetual` (بدون انقضا) · `--out license.txt` (ذخیره در فایل)

توکن خروجی را به مشتری بدهید تا در **پنل مدیریت ← ماژول‌ها ← ثبت لایسنس** وارد کند.

برای بررسی یک توکن: `npm run license -- verify <token>`
و برای دیدن فهرست و قیمت ماژول‌ها: `npm run modules`

### روش دوم: متغیر محیطی

در استقرارهایی که نمی‌خواهید لایسنس از پنل تغییر کند، آن را در `.env` بگذارید:

```
LICENSE=SALON1....
```

در این حالت پنل فقط وضعیت را نشان می‌دهد و امکان ویرایش ندارد.

### وقتی ماژولی فعال نباشد

- تب و صفحه‌ی مربوطه در پنل و در برنامه‌ی مشتری نمایش داده نمی‌شود
- مسیر مستقیم (URL) هدایت می‌شود
- API با خطای ۴۰۳ و نام ماژول پاسخ می‌دهد
- موتور قیمت‌گذاری تخفیف‌های آن ماژول را کلاً نادیده می‌گیرد
- **داده‌ها پاک نمی‌شوند**؛ با فعال شدن دوباره‌ی ماژول همه چیز برمی‌گردد

> هنگام توسعه: اگر `license-private.pem` روی دستگاه باشد، `npm run seed` یک لایسنس
> توسعه با همه‌ی ماژول‌ها می‌سازد. روی نصب مشتری این فایل وجود ندارد، پس فقط هسته فعال می‌ماند.

## اتصال سرویس پیامک

از مسیر **پنل مدیریت ← تنظیمات ← سرویس پیامک** یکی از گزینه‌ها را انتخاب و کلید API را وارد کنید:

| سرویس‌دهنده | مقدار «کلید API» | مقدار «شماره فرستنده» |
|---|---|---|
| کاوه‌نگار | API Key پنل | شماره خط (اختیاری) |
| sms.ir | `X-API-KEY` پنل | شماره خط |
| ملی‌پیامک | کلید وب‌سرویس (UUID) | شماره خط |
| حالت آزمایشی | — | — |

افزودن سرویس‌دهنده‌ی تازه: یک تابع به شیء `providers` در
[`server/lib/sms.js`](server/lib/sms.js) اضافه کنید و نامش را در `SMS_PROVIDERS` ثبت کنید.

## اتصال ایمیل (SMTP)

از **تنظیمات ← سرویس ایمیل** اطلاعات SMTP را وارد و با دکمه‌ی «بررسی اتصال» آزمایش کنید.
تا وقتی آدرس سرور خالی باشد، ایمیل‌ها فقط در ترمینال چاپ می‌شوند.

نمونه (Gmail با App Password): سرور `smtp.gmail.com`، پورت `587`، اتصال امن خاموش.

### نکته درباره‌ی تاریخ‌ها
تاریخ‌ها همیشه به صورت **میلادی `YYYY-MM-DD`** ذخیره و منتقل می‌شوند و فقط هنگام نمایش به
شمسی تبدیل می‌گردند. این کار منطق مقایسه و مرتب‌سازی را ساده و بدون خطا نگه می‌دارد.

### فونت
فونت **صمیم** (لایسنس SIL OFL، آزاد برای استفاده‌ی تجاری) به‌صورت محلی در
`client/public/fonts/` قرار دارد و از روی سرور خودتان سرو می‌شود — بدون وابستگی به
Google Fonts، پس آفلاین هم کار می‌کند و در ایران کند یا مسدود نمی‌شود.
متن لایسنس در کنار فایل‌های فونت نگهداری می‌شود (شرط OFL).

صمیم فقط دو وزن دارد، بنابراین در `@font-face` بازه‌ی وزن تعریف شده
(`400–500` معمولی و `600–900` توپر) و `font-synthesis: none` جلوی ساخت وزن مصنوعی
توسط مرورگر را می‌گیرد.

**تعویض فونت:** فایل‌های `woff2`/`woff` فونت تازه را در `client/public/fonts/` بگذارید،
بلوک `@font-face` بالای `client/src/styles.css` و متغیر `--font` را به‌روز کنید.

### پایگاه داده
داده‌ها در `server/data/db.json` نگهداری می‌شوند (بدون وابستگی نیتیو، بدون نیاز به نصب دیتابیس).
برای حجم کاری یک سالن کافی است؛ در صورت نیاز به مقیاس بیشتر، `server/lib/db.js` تنها فایلی است
که باید با SQLite یا PostgreSQL جایگزین شود.

> پیش از استفاده‌ی عملیاتی حتماً مقدار `JWT_SECRET` را در فایل `.env` تنظیم کنید
> (نمونه در `.env.example`) و از `server/data/` نسخه‌ی پشتیبان بگیرید.
